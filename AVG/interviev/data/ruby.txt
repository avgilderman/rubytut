Вопросы по Ruby

Вопрос 1. Какие типы данных используются в Ruby? Что такое массив? хэш? строка? число? время? символ?

Ответ 

#### Числа

Числа (`Numeric`) в Ruby выглядят так:

``` rb
5 # целое число Integer
-12 # отрицательное целое число
076 # восьмеричное число
0b010 # двоичное число
0x89 # шестнадцатиричное число
4.5 # число с плавающей точкой Float
2+3i # комплексное число Complex
Rational(2, 3) # рациональная дробь ⅔ Rational
```

#### Логический тип

Логический (булевый) тип — это вариация на тему «да» или «нет». В Ruby он представлен двумя
предопределёнными переменными `true` («истина» или «да») и `false` («ложь» или «нет»).
Появляется логический тип в результате логических операций или вызова логических методов (обычно заканчиваются на знак вопроса `?`).

Чаще всего логический тип возникает как результат сравнения.

`true` возвращает любой объект, в т.ч. `0`, за исключением `false` и `nil` (`nil` — это символ пустоты).

#### Массивы

Разработчики Ruby решили не реализовывать особых классов для динамических массивов, списков, стеков и тому подобного.
Они все это реализовали в массивах — структурах данных типа (или класса — в Ruby всё равно) `Array`.
Сделано это путём добавления специальных методов; например, методы `.push` и `.pop` для стека.

Особенности массивов в Ruby:

* Нет ограничений (это общий принцип языка). Массивы могут быть сколь угодно длинными.
* Динамичность: размер массива легко меняется.
* Гетерогенность: один массив может хранить данные разных типов.
* Библиотека итераторов на каждый случай жизни. Эта возможность позволяет не использовать циклы для обработки
данных в массивах, а, следовательно, избегать множества ошибок, связанных с неосторожным обращением с циклами.
Итераторы реализуются на высочайшем уровне.
* Много других методов. Все элементарные задачи для массивов решаются вызовом нужного метода.

``` rb
[1, 0, 740, 14, 25] # целочисленный массив

["a", "й", "6", 'Br', "Это массив строк"]

[[1, 2], [3, 4]] # двумерный целочисленный массив; Матрица — это объект класса Matrix

# Двумерный массив — это не матрица целых чисел
["1-й элемент смешанного массива", "7.343", [4, "вепрь"], [3, 67, 4326, 12, 3781357, 84221, "строка делает этот подмассив смешанным, но это не беда"]]

array = ["Этот массив пойдёт в переменную array", "Як-цуп-цоп, парви каридулла"]
```

#### Строки

Стро́ки (`String`) — это ряды букв и других символов. В Ruby стро́ки используют наработки языка Perl.

Стро́ки начинаются и заканчиваются `"` (программистскими кавычками) или `'` (машинописным апострофом).

Чаще [принято](https://github.com/rubocop-hq/ruby-style-guide#consistent-string-literals) использовать одинарные кавычки. Однако в случае интерполяции и применении спецсимволов таких, как `\t`, `\n`, `'`используются двойные.

Вот небольшой список их возможностей:
* Нет ограничений. Длина строки́ может достигать поистине фантастических размеров.
* Динамичность. Стро́ки можно расширять или уменьшать (для этого есть методы `+` и `[]`).
* Любой объект преобразуется в строку (методы `.inspect` и `.to_s` есть у любого объекта).
* Строка обладает обширной библиотекой методов, которые работают с правилами (это методы `.gsub`, `.match`,
`.scan`, `.split`).
* Конкатенация и интерполяция

``` rb
'2' + '2' #=> "22" # конкатенация

name = 'Вася'
"Привет, #{name}!" #=> "Привет, Вася" # интерполяция
```

#### Ассоциативные массивы

Ассоциативные массивы (класс `Hash`) подобны массивам упорядоченных пар.

Работают они подобно словарям: фигурная скобка символизирует боковой вид на открытую книгу, а стрелка `=>` покажет читателю связь каждой сущности с какой-то другой. Вторая фигурная скобка говорит, что пора закрывать книгу.

Структурными элементами хеша являются ключи и соответствующие им значения.

``` rb
hash = { "мама" => "мыла раму", 807 => "Это число улыбается!" }

hash["мама"] #=> "мыла раму"
hash["807"] #=> nil
hash[807] #=> "Это число улыбается!"
```

При использовании хешей в качестве аргументов метода возможна запись без фигурных скобок, а если в качестве ключа используются символы, то и без стрелок.

``` rb
Wife.new(age: 18, bust: 90, waist: 60, hips: 90)
```

Ассоциативные массивы оставляют возможность хранения данных разного типа только в ассоциативном виде.

#### Диапазоны значений

Чтобы было удобней получать подмассив или подстроку, был введён тип данных — диапазон (класс `Range`).

Диапазон формируется тремя элементами: начало, конец и тип протяжённости (символ `..` или `...`).

Начало и конец должны быть одного типа данных (одного класса) и быть перечислимыми, что значит, иметь метод `.succ` (succedent — «последующему»).

Применение `..` подразумевает включение конечного элемента. Применение `...` исключает конечный элемент.

Пример диапазонов:

``` rb
"a".."z"
"a"..."z" # то же, что и "a".."y"
1..100
1...100 # то же, что и 1..99
```

Начиная с версии 2.6.0 вводится понятие бесконечного диапазона.

Пример применения:

``` rb
array[3..] # возвратит массив с элементами array, соответствующие индексом от 3-го до последнего
```

#### Символы

В Ruby есть особый класс `Symbol`. Синтаксически объекты этого класса обозначаются двоеточием.

Например, `:a`, `:b`, `:symbol`.

Символ похож на строку (`String`). Одно из главных отличий заключается в том, что у каждого символа есть только один экземпляр.

Что это означает на практике? И в чём отличие от строки?

Например, у нас есть такие объекты:

```rb
a = "slovo"
b = "slovo"
c = "slovo"

d = :slovo
e = :slovo
f = :slovo
```

Дело в том, что в этом примере объекты `a`, `b` и `c` — это три разных объекта, они ссылаются на разные ячейки в памяти компьютера.

А вот объекты `d`, `e` и `f` — это всё один объект. В этом легко убедиться:

```rb
a.object_id #=> 47103948599080
b.object_id #=> 47103948574540
c.object_id #=> 47103948569400

d.object_id #=> 1294428
e.object_id #=> 1294428
f.object_id #=> 1294428
```

Символы часто используются в хэшах в качестве ключей. Одна из причин этого вытекает из свойств символов иметь лишь один экземпляр. Это позволяет экономить потребление памяти компьютера.

Ещё одно свойство символов — статичность. Т.е. к ним нельзя применить методы, подобные `downcase` или `+`.

И ещё одно важное применение символов, когда к ним применяется метод `to_proc`.

```rb
downator = :downcase.to_proc
downator.call('STROKA') #=> "stroka"
```

Как это работает? Дело в том, что в переменной `downator` хранится блок `proc { |arg| arg.downcase }`

На практике такое свойство часто применяют при операциях с массивами, например:

```rb
['STROKA', 'SLOVO'].map(&:downcase) #=> ["stroka", "slovo"]
```


Вопрос 2. Как хранится массив в памяти?
Ответ
В Ruby массивы являются динамическими структурами данных, которые хранят элементы в виде объектов. Чтобы понять, как они хранятся в памяти, нужно рассмотреть реализацию Ruby (например, MRI — Matz's Ruby Interpreter, основная реализация на C).
Как устроен массив в памяти:

Внутренняя структура:

В MRI массив реализован как структура RArray, которая содержит:

Указатель на область памяти, где хранятся элементы (массив указателей на объекты Ruby).
Размер массива (количество элементов).
Ёмкость (выделенное место для хранения элементов).


Элементы массива — это указатели на объекты Ruby (VALUE), которые могут быть числами, строками, другими массивами и т.д.
Пример структуры в C (упрощённо):
cstruct RArray {
struct RBasic basic; // Базовые метаданные (тип, флаги)
VALUE *ptr;         // Указатель на элементы
long len;           // Текущая длина
long capa;          // Ёмкость
};



Хранение элементов:

Каждый элемент массива — это указатель (VALUE) на объект в куче (heap).
Если массив содержит примитивы (например, Fixnum, т.е. небольшие целые числа), они могут храниться непосредственно в VALUE (inline) благодаря оптимизации в MRI (теггинг указателей).
Для сложных объектов (строки, хэши) указатель ссылается на их данные в куче.


Динамическое выделение памяти:

При создании массива (например, []) Ruby выделяет начальную ёмкость (обычно небольшую, например, 8 элементов).
При добавлении элементов (например, через <<) массив может расширяться:

Если текущая ёмкость превышена, Ruby вызывает realloc для увеличения памяти, обычно удваивая ёмкость.
Это делает операции добавления в конец массива амортизированно O(1), но иногда O(n) при перераспределении.




Особенности:

Копирование при записи (Copy-on-Write): В MRI массивы используют оптимизацию, чтобы избежать копирования данных до их изменения (если массив разделяется между потоками).
Гарбадж-коллектор: Объекты в массиве отслеживаются сборщиком мусора, который освобождает память, если объект больше не используется.
Смешанные типы: Так как Ruby — динамически типизированный язык, массив может содержать объекты разных типов, что увеличивает накладные расходы на хранение указателей.



Пример:
rubyarr = [1, "hello", [2, 3]]

В памяти:

arr указывает на структуру RArray.
ptr содержит три указателя:

На Fixnum 1 (хранится как непосредственное значение в VALUE).
На объект String "hello" (указатель на данные строки в куче).
На другой массив [2, 3] (указатель на другую структуру RArray).





Итог:
Массивы в Ruby хранятся как динамически расширяемые списки указателей на объекты в куче. Это обеспечивает гибкость (разные типы данных), но увеличивает накладные расходы по сравнению с массивами в языках вроде C, где данные хранятся последовательно.

Вопрос 3. Какую структуру данных применить для проверки "парности скобок" вида `([])` и `([[))`?
Ответ
Для проверки парности скобок (например, ([]) — корректно, ([[)) — некорректно) лучше всего использовать стек (stack). Это оптимальная структура данных, так как скобки должны быть сбалансированы: каждая открывающая скобка должна иметь соответствующую закрывающую в правильном порядке.
Почему стек:

Принцип LIFO (Last In, First Out): Последняя открытая скобка должна быть закрыта первой.
Алгоритм проверяет парность, добавляя открывающие скобки в стек и удаляя их при нахождении соответствующих закрывающих скобок.

Алгоритм:

Создайте пустой стек (в Ruby можно использовать массив как стек).
Пройдите по строке посимвольно:

Если символ — открывающая скобка ((, [, {), добавьте его в стек (push).
Если символ — закрывающая скобка (), ], }):

Проверьте, пуст ли стек (если да, то строка некорректна — лишняя закрывающая скобка).
Извлеките верхний элемент стека (pop) и проверьте, соответствует ли он текущей закрывающей скобке.




После обработки строки проверьте, пуст ли стек:

Если пуст — строка корректна (все скобки сбалансированы).
Если не пуст — строка некорректна (есть незакрытые скобки).



Реализация в Ruby:
rubydef balanced?(str)
stack = []
brackets = { '(' => ')', '[' => ']', '{' => '}' }

str.each_char do |char|
if brackets.key?(char)
stack.push(char) # Открывающая скобка
elsif brackets.value?(char)
return false if stack.empty? || brackets[stack.pop] != char # Несоответствие или лишняя закрывающая
end
end

stack.empty? # Пустой стек — все скобки закрыты
end

# Примеры
puts balanced?("([])")   # true
puts balanced?("([[))")  # false
puts balanced?("({[]})") # true
puts balanced?("([)]")   # false
Объяснение кода:

Стек: Массив stack используется как стек (методы push и pop).
Хэш brackets: Хранит пары открывающих и закрывающих скобок для удобной проверки.
Проверка:

Если встречается открывающая скобка, она добавляется в стек.
Если встречается закрывающая, она сравнивается с последней открывающей из стека.
Если стек пуст при встрече закрывающей скобки или скобки не соответствуют, возвращается false.


Итог: Если после обработки строки стек пуст, скобки сбалансированы.

Сложность:

Временная: O(n), где n — длина строки (один проход по символам).
Пространственная: O(n) в худшем случае, если строка состоит только из открывающих скобок.

Почему не другие структуры:

Очередь: Не подходит, так как порядок обработки скобок должен быть LIFO, а не FIFO.
Хэш: Не нужен, так как нет необходимости хранить пары ключ-значение для поиска (хэш используется только для сопоставления скобок).
Массив без стека: Можно использовать массив, но стек — наиболее естественная абстракция для этой задачи.

Альтернативы:

Для простых случаев можно использовать счётчик (например, для проверки только круглых скобок), но стек универсален для разных типов скобок ((), [], {}).

Вопрос 4. Почему в Ruby `1660 / 100 ≠ 16.6`?


Ответ 
Если все аргументы арифметического выражения целые числа, то результат будет целым, если хотя бы одно число с плавающей запятой, то результат будет числом с плавающей запятой.

Таким образом, чтобы получить `16.6` нужно чтобы одно из чисел имело тип `Float`.

https://stackoverflow.com/questions/5502761/why-is-division-in-ruby-returning-an-integer-instead-of-decimal-value


Вопрос 5. Почему в Ruby `24.0 * 0.1 ≠ 2.4`?

Ответ 
Поскольку внутренне компьютеры используют формат (binary floating point), который не может точно представить число как 0.1, 0.2 или 0.3.

Когда код компилируется или интерпретируется, ваш «0.1» уже округляется до ближайшего числа в этом формате, что приводит к небольшой ошибке округления даже до того, как произойдет вычисление.

https://floating-point-gui.de/basic/

https://github.com/rdp/ruby_tutorials_core/wiki/Ruby-Talk-FAQ#floats_imprecise

https://en.wikipedia.org/wiki/Floating-point_arithmetic#Accuracy_problems


Вопрос 6. Какие структуры есть в ruby?


Ответ 
Что такое struct, abstract, open struct
Структуры в Руби следующие:

* `struct`
* `abstract`
* `openstruct`

Структуры позволяют так же работать с методами по примеру полного аналога класса.  Полностью заменяют классы и возможно даже немного удобнее их. Но все пишут что не надо заменять структуры на классы полностью, они могут быть хороши только в не больших размерах и объемах коллекций.

struct и open struct это упрощенная форма создания классов, в котором мы указываем что должно быть передано в struct для вывода программы.

* struct — принимает четкое кол-во параметров для вывода программы.

``` rb
person = :name, :age

p.name = "Karthik"
p.age = 30

puts "Hello, I am #{p.name}, age #{p.age}"
```

либо

``` rb
person =  :name, :age

p =  "Karthik", 30

puts "Hello, I am #{p.name}, age #{p.age}"
```

OpenStruct — не ругается, если параметров передано больше чем есть.

``` rb
require 'ostruct'

p.name= "Karthik"
p.age = 30

puts "Hello, I am #{p.name}, age #{p.age}"
```


Вопрос 7. Что такое `loop`, `while`, `map`, `each`?


Ответ 

`loop`, `while` — это управляющие конструкции, создающие циклы, повторение кода по условию/без условий.

`each`, `map` — итераторы, перебирают все элементы у объекта (унаследованы от `Numerable`).

Итераторы — это методы, которые принимают блоки и выполняют код в блоках для элементов коллекций (массивов, интервалов или хэшей).

Вопрос 11. Какие переменные бывают, где они используются, где они доступны (поля видимости)?


Ответ 

Локальные переменные `variable` — локальная переменная, она доступна только в той области видимости, где была определена.

Переменные экземпляра класса `@variable` — доступны только в методах экземпляра класса, где они определены. При первом вызове возвращают `nil`.

Глобальные переменные `$variable` — область видимости — вся программа (опасно использовать, т.к. потом сложно изменить, где и кто её поменял).

Переменные класса `@@variable` — область видимости — класс в котором они определены и все экземпляры данного класса.

http://rubycode.ru/ruby/osnovy/54-oblast-vidimosti-i-tipy-obektov.html


Вопрос 12. Что такое переменная с одной `@` и переменная с двумя `@@`?


Ответ 

Переменные экземпляра класса `@variable` — начинаются с `@`. Переменные экземпляра класса доступны в методах экземпляра класса, где они определены.

Вопрос 18. Что такое синглтон-методы и синглтон-классы?

```rb
end

dog.barking
# => "WOOF! WOOF!"
dog.singleton_methods
# => [:barking]

cat.singleton_methods
# => []
```

Методы класса (`self`-методы) на самом деле тоже являются синглтон-методами класса `Class`.

Таким образом, в Руби все методы принадлежат какому-то классу.

Синглтон-класс — это анонимный класс, в котором размещаются синглтон-методы объекта.

```rb
dog.singleton_class
# => #<Class:#<Animal:0x000055a121433970>>

# => true

cat.singleton_class.method_defined?(:barking)
# => false
```

Синглтон-класс встраивается в путь наследования и поиска метода интерпретатором Ruby.

```rb
dog.singleton_class.superclass
# => Animal
```

Вопрос 26. Что такое `proc`, `lambda`, `block`? И какие отличия есть между ними?


Ответ 
Это анонимные функции, которые представляют из себя блоки.

`lambda` требует чтобы кол-во аргументов в блоке, соответствовало преданным в блок, так же `lambda` возвращает значение без блока, можно вызвать на переменной метод `call` и передать к примеру `return 'any'`, `lambda` выведет.

Вопрос 27. Многопоточность в ruby?
Ответ
Многопоточность в Ruby позволяет выполнять несколько задач параллельно в рамках одного процесса, используя потоки (threads). Однако реализация многопоточности в Ruby имеет свои особенности, особенно в MRI (Matz's Ruby Interpreter).
Особенности многопоточности в Ruby:

GIL (Global Interpreter Lock):

В MRI (основной интерпретатор Ruby) существует GIL, который ограничивает выполнение Ruby-кода в нескольких потоках одновременно. Это значит, что даже в многопоточной программе только один поток может выполнять Ruby-код в данный момент.
GIL не блокирует системные вызовы (например, I/O-операции: чтение файлов, сетевые запросы), поэтому многопоточность эффективна для I/O-bound задач (например, веб-серверов).
Для CPU-bound задач (например, вычисления) GIL ограничивает параллелизм. Альтернативы: JRuby или Rubinius (без GIL) или использование процессов вместо потоков.


Создание потоков:

Потоки создаются с помощью класса Thread:
rubythread1 = Thread.new do
5.times { puts "Thread 1"; sleep 1 }
end
thread2 = Thread.new do
5.times { puts "Thread 2"; sleep 1 }
end
thread1.join
thread2.join
Метод join заставляет главный поток ждать завершения других.


Типы задач:

I/O-bound: Многопоточность в Ruby эффективна для задач, связанных с ожиданием (например, HTTP-запросы, чтение/запись в БД). Пример: веб-сервер Puma использует потоки для обработки запросов.
CPU-bound: Для вычислительных задач лучше использовать процессы (через fork или гемы вроде parallel) или другие интерпретаторы (JRuby).


Синхронизация потоков:

Для предотвращения конфликтов (например, при доступе к общим данным) используются механизмы синхронизации:

Mutex:
rubymutex = Mutex.new
counter = 0
threads = 5.times.map do
Thread.new do
mutex.synchronize { counter += 1 }
end
end
threads.each(&:join)
puts counter # 5

ConditionVariable, Queue — для координации потоков.


Thread-safe структуры: Гем concurrent-ruby предоставляет потокобезопасные коллекции (например, Concurrent::Array).


Альтернативы потокам:

Процессы: Используйте fork или гемы (parallel, sidekiq) для параллелизма без GIL.
ruby3.times do
fork { puts "Child process #{Process.pid}" }
end
Process.waitall

Ractor (в Ruby 3.0+): Экспериментальный механизм для настоящего параллелизма:
rubyr1 = Ractor.new { sleep 1; puts "Ractor 1" }
r2 = Ractor.new { sleep 1; puts "Ractor 2" }
r1.take
r2.take




Проблемы и решения:

Проблемы:

GIL ограничивает CPU-bound задачи.
Риск состояния гонки (race conditions) при работе с общими данными.


Решения:

Используйте потоки для I/O-bound задач.
Применяйте Mutex или concurrent-ruby для синхронизации.
Для CPU-bound задач используйте процессы или Ractor.



Применение:

Веб-серверы (Puma, Thin) используют потоки для обработки множества HTTP-запросов.
Фоновые задачи (Sidekiq) используют процессы или потоки для асинхронной обработки.

Вопрос 30. Что такое safe navigation?


Ответ 

В новом синтаксисе выражение из примеров можно записать так:

`image = user&.profile&.thumbnails&.large`

Оператор применяется для сокращения выражений, где выполняется проверка существования объекта и
затем обращение к методу объекта только в случае положительной проверки:

`obj.nil? && obj.some_method`

Вместе с лаконичным видом такая реализация дает быструю проверку на `nil`,
так как изменения реализованы на уровне парсера и ruby-код в проверках не участвует.
После того, как встретился `nil`, дальнейшее выполнение цепочки прерывается.
Проверка выполняется именно на `nil`, а не на логическое условие,
поэтому если результатом окажется `false`, то выполнение будет успешно продолжено по цепочке дальше.

Если в метод передаются аргументы, то, в отличие от `try`,
они вычисляются только в том случае, если объект существует и метод реально вызывается.
Например, для ActiveSupport в выражении `obj.try(:foo, bar())` всегда будет выполняться `bar()`,
даже если `obj` не существует. Но в выражении `obj&.foo(bar())`,
аргумент `bar()` будет вычислен только тогда, когда `obj` не равен `nil`.

Вопрос 34. Какую сортировку использует метод `sort` в ruby?
Ответ
Метод sort в Ruby (для массивов) использует алгоритм быстрой сортировки (Quicksort) в реализации MRI (Matz's Ruby Interpreter).
Подробности:

Реализация:

В MRI метод Array#sort реализован на уровне C и использует модифицированный Quicksort.
Quicksort выбирает опорный элемент (pivot), разбивает массив на подмассивы (меньше и больше pivot) и рекурсивно сортирует их.
Для небольших массивов (обычно менее 10 элементов) Ruby может использовать сортировку вставками (Insertion Sort), так как она быстрее для маленьких наборов данных.


Сложность:

Средняя: O(n log n) — для большинства случаев.
Худшая: O(n²) — если выбор pivot неудачен (например, уже отсортированный массив), но Ruby использует оптимизации (например, случайный pivot), чтобы минимизировать этот случай.
Пространственная: O(log n) — для рекурсивного стека.


Особенности:

Метод sort по умолчанию сравнивает элементы с помощью оператора <=> (метод Comparable).
Можно передать блок для пользовательской сортировки:
rubyarr = [3, 1, 4, 1, 5]
arr.sort # => [1, 1, 3, 4, 5]
arr.sort { |a, b| b <=> a } # => [5, 4, 3, 1, 1] (обратный порядок)

sort! — модифицирует массив на месте.


Пример:
ruby# Сортировка строк
names = ["Bob", "Alice", "Charlie"]
names.sort # => ["Alice", "Bob", "Charlie"]

# Сортировка с блоком
names.sort { |a, b| a.length <=> b.length } # => ["Bob", "Alice", "Charlie"] (по длине)

Оптимизации:

Ruby использует улучшенный Quicksort с оптимизациями, такими как:

Выбор pivot (например, медиана из нескольких элементов).
Переключение на Insertion Sort для маленьких подмассивов.


В JRuby или других реализациях алгоритм может отличаться (например, использовать Java’s Arrays.sort).



Итог:
Метод sort в Ruby использует Quicksort с оптимизациями (и Insertion Sort для малых массивов). Это обеспечивает хорошую производительность для большинства случаев, с возможностью настройки через пользовательский блок.
