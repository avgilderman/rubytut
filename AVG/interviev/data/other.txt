Вопрос 1. Интерпретируемые vs комилируемые языки, в чём разница?
Ответ
Интерпретируемые языки:

Код выполняется интерпретатором построчно во время выполнения, без предварительного преобразования в машинный код.
Примеры: Python, Ruby, JavaScript.
Как работает: Интерпретатор читает исходный код, анализирует его и выполняет команды на лету.
Преимущества:

Гибкость: проще отлаживать и изменять код (например, в интерактивных оболочках).
Платформонезависимость: код не привязан к конкретной архитектуре.
Быстрая разработка: нет необходимости в компиляции.


Недостатки:

Медленнее, так как код интерпретируется во время выполнения.
Зависимость от интерпретатора.


Пример: Python-код (print("Hello")) выполняется интерпретатором Python.

Компилируемые языки:

Код преобразуется компилятором в машинный код (или промежуточный байт-код) до выполнения.
Примеры: C, C++, Rust, Go.
Как работает: Компилятор переводит исходный код в исполняемый файл (например, .exe для Windows), который затем запускается.
Преимущества:

Высокая производительность: машинный код оптимизирован для процессора.
Нет зависимости от интерпретатора во время выполнения.
Обнаружение ошибок на этапе компиляции (например, синтаксические или типовые).


Недостатки:

Дольше процесс разработки из-за необходимости компиляции.
Платформозависимость: исполняемый файл привязан к архитектуре (например, x86 или ARM).


Пример: C-код компилируется с помощью gcc в исполняемый файл.

Гибридные подходы:

Некоторые языки (например, Java, C#) компилируются в промежуточный байт-код, который затем интерпретируется или JIT-компилируется (Just-In-Time) во время выполнения.
Пример: Java компилируется в байт-код для JVM.

Вопрос 2. Что такое рефакторинг?


Ответ 
Рефакторинг представляет собой процесс такого изменения программной системы, при котором не меняется внешнее поведение кода, но улучшается его внутренняя структура. Это способ систематического приведения кода в порядок, при котором шансы появления новых ошибок минимальны.

В сущности, при проведении рефакторинга кода вы улучшаете его дизайн уже после того, как он написан.

Вопрос 12. 
Ответ
Что такое хешфункции (md5, sha1/2), какими свойствами обладают?
Хеш-функции — это алгоритмы, которые преобразуют входные данные (например, строку или файл) в строку фиксированной длины (хеш), которая выглядит случайной. Примеры: MD5, SHA-1, SHA-2.
Как работают:

Принимают данные произвольного размера.
Возвращают хеш фиксированной длины (например, MD5 — 128 бит, SHA-256 — 256 бит).
Пример (в Ruby):
rubyrequire 'digest'
puts Digest::MD5.hexdigest('hello') # => "5d41402abc4b2a76b9719d911017c592"
puts Digest::SHA256.hexdigest('hello') # => "2cf24dba..."


Свойства хеш-функций:

Детерминированность: Один и тот же вход всегда даёт один и тот же хеш.
Быстрота: Вычисление хеша выполняется быстро.
Односторонность: Нельзя восстановить исходные данные из хеша.
Устойчивость к коллизиям:

Сложно найти два разных входа, дающих одинаковый хеш (сильная устойчивость).
Сложно найти другой вход с тем же хешем для данного входа (слабая устойчивость).


Малое изменение входа → большой выходной эффект: Даже изменение одного бита в данных сильно меняет хеш.
MD5, SHA-1, SHA-2:

MD5:

Длина: 128 бит.
Использование: Проверка целостности файлов (устарел для безопасности).
Проблемы: Уязвим к коллизиям, не рекомендуется для криптографии.


SHA-1:

Длина: 160 бит.
Использование: Цифровые подписи, Git (хеширование коммитов).
Проблемы: Уязвим к атакам (коллизии найдены), устарел для безопасности.


SHA-2 (SHA-256, SHA-512):

Длина: 256 или 512 бит.
Использование: Криптография, цифровые подписи, блокчейн.
Преимущества: Высокая устойчивость к коллизиям, современный стандарт.



Применение:

Проверка целостности данных (например, контрольные суммы файлов).
Хранение паролей (с солью, например, через bcrypt).
Цифровые подписи и сертификаты.

Пример в Ruby (хеширование пароля):
rubyrequire 'bcrypt'
password = BCrypt::Password.create('my_password') # Хеширование с солью
puts password # => "$2a$12$..."
puts password == 'my_password' # => true

Вопрос 13. Чем отличаются массив и связный список?
Ответ
Массив:

Структура: Последовательный блок памяти, где элементы хранятся в непрерывной области.
Доступ: Прямой доступ по индексу (O(1)).
Хранение: Фиксированный или динамический размер (в Ruby массивы динамические).
Пример в Ruby: arr = [1, 2, 3].

Связный список:

Структура: Элементы (узлы) хранятся отдельно, каждый узел содержит данные и указатель на следующий (или предыдущий) узел.
Доступ: Последовательный (O(n) для доступа к элементу).
Хранение: Гибкий размер, элементы не требуют непрерывной памяти.
Пример в Ruby:
rubyclass Node
attr_accessor :value, :next
def initialize(value)
@value = value
@next = nil
end
end

Вопрос 14. Какие операции быстрее в массиве, какие в связном списке?
Ответ
Массив:

Быстрее:

Доступ по индексу: O(1), так как элементы хранятся последовательно.
Итерация: Линейное чтение (O(n)) эффективно благодаря кэшированию памяти.
Копирование: Быстро для больших блоков данных.


Медленнее:

Вставка/удаление: O(n), так как требуется сдвиг элементов (например, arr.insert(0, value)).
Изменение размера: При превышении ёмкости требуется перераспределение памяти (O(n)).



Связный список:

Быстрее:

Вставка/удаление: O(1), если известен узел (достаточно изменить указатели).
rubynode.next = new_node # O(1)

Добавление в начало/конец: O(1) (в двусвязном списке).


Медленнее:

Доступ по индексу: O(n), так как нужно пройти по узлам.
Поиск: O(n), так как нет прямого доступа.



Пример в Ruby:

Массив: arr[5] — мгновенно.
Связный список: доступ к 5-му элементу требует прохода по 5 узлам.

16. С какими алгоритмами сортировки сталкивался?
Ответ
Я могу описать алгоритмы сортировки, которые часто используются или обсуждаются в программировании, включая Ruby. Вот основные:

Quicksort:

Используется в Ruby (Array#sort).
Средняя сложность: O(n log n).
Худшая: O(n²).
Особенность: Эффективен для большинства случаев, оптимизирован выбором pivot.


Merge Sort:

Сложность: O(n log n) всегда.
Особенность: Стабильная сортировка, требует дополнительной памяти O(n).
Применение: Хорошо для больших данных, особенно в связанных списках.


Insertion Sort:

Сложность: O(n²), но O(n) для почти отсортированных массивов.
Особенность: Простая, эффективна для малых массивов (используется в Ruby для подмассивов в Quicksort).
Пример:
rubydef insertion_sort(arr)
(1...arr.length).each do |i|
key = arr[i]
j = i - 1
while j >= 0 && arr[j] > key
arr[j + 1] = arr[j]
j -= 1
end
arr[j + 1] = key
end
arr
end



Bubble Sort:

Сложность: O(n²).
Особенность: Простая, но неэффективная для больших данных.
Применение: Обучение, редко используется в реальных проектах.


Heap Sort:

Сложность: O(n log n).
Особенность: Использует структуру кучи, не требует дополнительной памяти для рекурсии.
Применение: Когда нужна стабильная производительность.


Selection Sort:

Сложность: O(n²).
Особенность: Минимальное количество обменов, но медленный поиск минимума.
Применение: Обучение.



Применение в Ruby:

Array#sort использует Quicksort с оптимизациями (например, Insertion Sort для малых массивов).
Для пользовательской сортировки:
rubyarr.sort_by { |x| x.length } # Для сортировки по длине строки


Когда использовать:

Quicksort: Универсальный выбор (используется в Ruby по умолчанию).
Merge Sort: Для стабильности или связанных списков.
Insertion Sort: Для малых или почти отсортированных массивов.
